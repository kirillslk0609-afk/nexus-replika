# Проверка на Android и демонстрация

## Сначала выяснить у организаторов

1. На каком устройстве, Android и RAM проходит проверка? Каков лимит времени обработки?
2. Язык, длительность, форматы записей; диапазон числа участников; наличие одновременной речи.
3. Достаточно ли локальной LLM для пунктуации? Какая функция от неё ожидается?
4. Как оцениваются диаризация, временные метки и пустые результаты? Как нормализуют текст для WER?
5. Предельный размер APK и способ передачи больших файлов; точный срок предварительной отправки APK.

Для самого первого запуска перенесите на телефон `samples/russian.wav`. В нём 10 секунд русской речи; исходный текст лежит рядом. Затем обязательно проверьте настоящие разговоры людей.

## Приёмка на физическом телефоне

Список ниже намеренно не отмечен: результаты эмулятора не подменяют проверку телефона.

- [ ] APK устанавливается на телефон с нуля.
- [ ] В авиарежиме на первом запуске все модели доступны.
- [ ] WAV с двумя разными голосами даёт реальные слова и устойчивые ID.
- [ ] Русская речь остаётся русской, числа не переписываются LLM.
- [ ] MP3 и M4A импортируются и имеют правильную длительность.
- [ ] Времена реплик совпадают с прослушиванием; поздние реплики не смещены после пауз.
- [ ] JSON открывается внешним приложением и соответствует контракту.
- [ ] Приложение не зависает при обработке; поворот экрана не запускает второй инференс.
- [ ] Отмена дожидается текущего этапа и возвращает управление; повторный запуск работает.
- [ ] Тишина/пустой/повреждённый файл не дают выдуманную расшифровку или аварийное завершение.
- [ ] После закрытия и открытия виден последний завершённый результат.
- [ ] Сравнены чистая запись и её шумная копия: текст, пропуски, повторения слов; говорящие и времена не меняются из-за ASR.
- [ ] Замерены RAM, холодный и повторный запуск, время обработки и WER на трёх собственных записях.

## Сценарий демонстрации, 2–3 минуты

1. Показать авиарежим, название приложения и короткую заранее скачанную аудиозапись.
2. Выбрать файл и запустить обработку. Ускорение видео допустимо только с явной подписью; время обработки показать отдельно.
3. Показать двух говорящих, реплики и переход по времени к звуку.
4. Экспортировать JSON и открыть его.
5. Объяснить роли ASR, диаризации и LLM, показать архитектуру и честно назвать ограничения.

В `artifacts/demo/` подготовлена запись работы приложения в эмуляторе. Для подтверждения работы на телефоне повторите этот сценарий на физическом устройстве.
