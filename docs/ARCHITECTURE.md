# Архитектура

## Поток данных

```text
Системный выбор файла
        ↓
Копия в приватное хранилище приложения
        ↓
WAV Reader / MediaExtractor + MediaCodec
        ↓
Mono float PCM 16 kHz
        ↓
pyannote: локальные голоса в окнах 10 с, шаг 5 с
        ↓
TitaNet-Small: признаки чистых участков речи
        ↓
Адаптивная кластеризация и согласование перекрывающихся окон
        ↓
Регионы говорящих на абсолютной временной шкале
        ↓
Whisper small INT8 на каждой реплике (не более 25 секунд)
        ↓
Qwen2.5-0.5B-Instruct Q4_K_M / llama.cpp
        ↓
Проверка неизменности последовательности слов
        ↓
Список реплик + JSON через системный диалог сохранения
```

Все стрелки после импорта выполняются внутри Android-процесса. Серверов, внешних API, удалённого инференса и заранее приготовленных расшифровок нет.

## Модели

1. **Речь:** многоязычный Whisper small в ONNX INT8, движок sherpa-onnx 2.0.1. Вариант `.en` не используется. По умолчанию русский язык; есть английский и автоопределение.
2. **Границы голосов:** pyannote segmentation 3.0 в ONNX INT8.
3. **Признаки говорящего:** NVIDIA NeMo TitaNet-Small, ONNX, 192-мерные векторы, 16 кГц. В версии 0.2 заменяет CAMPPlus. Число голосов определяется по записи; оно не задаётся равным двум. Алгоритм описан ниже.
4. **Локальная LLM:** Qwen2.5-0.5B-Instruct в GGUF Q4_K_M, CPU-инференс llama.cpp через собственный JNI-мост. Модель восстанавливает пунктуацию. Если слова/числа изменены, результат модели отклоняется и сохраняется исходный ASR-текст. LLM реально запускается, число вызовов показывается в приложении. Число генерируемых токенов ограничено длиной исходной реплики: clamp(2 × число токенов + 32, 64, 512). Проверяются также знак числа, проценты и числовые разделители.

Роль LLM нужно подтвердить у организаторов: PDF требует локальную LLM, но не уточняет её обязательную функцию.

## Декодирование

WAV читается блоками по 64 КиБ. Каналы смешиваются в моно. При понижении частоты выше 16 кГц применяется FIR-фильтр с окном Хэмминга и частотой среза 7,2 кГц перед интерполяцией. Задержка фильтра компенсируется; длина записи и абсолютная шкала времени сохраняются. Это антиалиасинговая фильтрация, не шумоподавление.

## Диаризация 0.2

`StableDiarizer` передаёт pyannote окна не длиннее 10 секунд с шагом 5 секунд. Используется локальная сегментация sherpa без её глобальной кластеризации коротких фрагментов. В каждом окне речь одного локального участника объединяется, одновременная речь исключается из материала для голосовых признаков.

TitaNet извлекает вектор для дорожек с минимум 0,5 с чистого звука. Новые группы формируются по дорожкам от 1,5 с; если таких нет, используются доступные короткие. Векторы нормализуются, далее применяется агломеративная кластеризация со средним косинусным расстоянием. Кандидаты рассматриваются в диапазоне 0,25–0,95 с шагом 0,025. Выбирается разделение с лучшим взвешенным silhouette score за вычетом 0,05 за каждую дополнительную группу. Это эвристика выбора сложности, не фиксированное число говорящих.

Группы с суммарным материалом меньше max(2,5 с; 5% материала) не создают нового участника: их фрагменты сопоставляются с ближайшим центром. Суммарный материал учитывает перекрывающиеся окна, это не уникальная длительность речи. Для единственного голоса используется проверка малого разброса признаков. Короткие дорожки получают ближайший ID; дорожки без вектора используют совпадение по времени с надёжными соседними окнами. Они не удаляются.

На сетке 20 мс окна голосуют за говорящих; середина окна весит больше края. Число одновременно активных голосов также определяется голосованием. Сегменты короче 150 мс отбрасываются. На выходе сохраняются абсолютные времена и перекрытия. Сегментатор освобождается до загрузки отдельного экстрактора; все нативные ресурсы освобождаются в `finally`. Между окнами, дорожками и шагами кластеризации проверяется отмена.

Ни имена тестовых файлов, ни ожидаемое число участников, ни исходные стереоканалы не передаются этому алгоритму. Стереоканалы используются **только внешним скриптом оценки**, приложение получает моно PCM.

## Ускорение декодирования и локальной LLM в версии 0.4

Веса ASR, модели и алгоритмы диаризации сохранены. Для сжатого аудио изменена организация работы MediaCodec, для LLM — обработка ответов. Перед каждой новой генерацией LLM внутренний KV-кеш очищается полностью, как в 0.3.

- MediaCodec работает асинхронно: callback-поток подаёт входные пакеты, а вызывающий рабочий поток обрабатывает готовый PCM. Очередь ограничена восемью событиями; изменения формата и выходные буферы проходят в исходном порядке. Поля BufferInfo копируются. При отмене разблокируется очередь, ожидается завершение текущего чтения входа, останавливается кодек и присоединяется callback-поток до освобождения MediaExtractor. Проверка остановки без выхода 30 с сохранена. Сведение в моно, FIR-фильтр, ресемплер и порядок арифметики не изменены. Побитовые проверки сравнивают каждый float32-сэмпл со старым синхронным путём. [MediaCodec callbacks](https://developer.android.com/reference/android/media/MediaCodec#setCallback(android.media.MediaCodec.Callback,%20android.os.Handler)).
- `PunctuationPrefixGuard` проверяет только завершённые слова перед ASCII-пробелом/табуляцией/переносом. Пока UTF-8 символ не закончен, решение откладывается. Обнаружение несовместимого слова останавливает бесполезное продолжение; неизменённый итоговый фильтр возвращает исходный ASR-текст. Ограничение длины и проверка чисел остаются в итоговом фильтре.
- До 64 ответов LLM запоминаются по точному входному тексту в пределах записи. На новую запись кеш не переносится. Результат выдаётся повторно только при идентичной строке; кэширование не использует имя файла или эталон теста. В UI учитываются фактические нативные генерации, обращения к кешу не добавляют фиктивных вызовов.
- `EngineResult.timingsMs` содержит длительности подготовки, декодирования, диаризации, загрузки/вызовов ASR и LLM для тестового отчёта. Экспортируемый JSON не изменён.

[Парные измерения и проверки](SPEED_RESULTS.md) сравнивают оптимизированный и прежний алгоритмы на одинаковых входах. Сравнение LLM после прогрева отдельно от полного процесса; в полном процессе учтены первая инструкция и загрузка моделей.

## Устойчивость ASR к шуму

В версии 0.3 использован Whisper small INT8 вместо base. Шумоподавляющий фильтр не применяется: проверенные варианты ухудшали часть русских примеров. Диаризация по-прежнему получает исходный декодированный PCM, без обработки для ASR.

`SpeechRecognizer` держит одну ASR-сессию на запись. Если в тексте не менее восьми повторений одного слова, занимающих от 65% слов, либо трёхсловная последовательность повторяется минимум четыре раза с покрытием от 70%, выполняется один дополнительный проход. К копии аудиофрагмента добавляется 200 мс нулей с каждой стороны. Времена и говорящий остаются из исходного фрагмента. Непустой повторный результат без обнаруженного цикла заменяет зацикленный; в остальных случаях сохраняется исходный текст. Это эвристика, которая может сработать на действительно повторяемой речи. Отмена проверяется перед и после нативного вызова, потоки и сессия освобождаются в `finally`.

Эталоны и результаты сравнения доступны только тестам. Модель и критерий повтора не получают правильную расшифровку. [Измерения и ограничения](NOISE_RESULTS.md).

## Реплики и метки

ID нормализуются по первому появлению голоса (`speaker_1`, `speaker_2`, …), а не по произвольному номеру кластера. Один ID сохраняется на протяжении записи.

Временные метки берутся из обнаруженных звуковых регионов, не генерируются LLM. Расчёт идёт относительно исходной записи, паузы не вырезаются из временной шкалы. Соседние регионы одного голоса с разрывом до 200 мс объединяются, если общая длина не больше 25 секунд. Более длинные регионы делятся. Это базовые границы речи, а не точное пословное выравнивание.

При одновременной речи сохраняются перекрывающиеся временные интервалы. Источники звука не разделяются, поэтому текст таких интервалов может смешиваться или дублироваться. Это явно указано в интерфейсе и ограничениях.

## Память, жизненный цикл и безопасность данных

- Модели диаризации, распознавания и LLM загружаются по очереди, нативные объекты освобождаются через `finally`/`close`.
- PCM хранится в памяти, поэтому введено ограничение 15 минут (около 58 МБ для готового float32 mono 16 kHz без учёта временных буферов и моделей).
- Веса внутри APK копируются в приватную папку и проверяются SHA-256. Запись через временный файл защищает от частичного копирования. Внутри процесса повторная проверка кешируется по пути, ожидаемому хешу, размеру и времени изменения; новый процесс проверяет хеш заново.
- Работа идёт вне UI-потока. ViewModel переживает поворот экрана. Последний полный результат сохраняется атомарно.
- Отмена проверяется при копировании, декодировании, между этапами/репликами. Длинный нативный вызов немедленно не прерывается.
- В первой версии нет foreground service: приложение следует держать открытым. После убийства процесса незавершённая обработка не возобновляется.
- У приложения нет `INTERNET`, разрешения на микрофон и общего доступа ко всему хранилищу. Доступ к выбранному файлу выдаёт системный диалог.
- Локальные аудиоданные удаляются вместе с приложением; новая запись заменяет старую. В манифесте установлено `allowBackup=false`; отдельные правила переноса данных Android 12+ пока не заданы.

## RTF

`RTF = время обработки / длительность аудиозаписи`. Время включает декодирование, загрузку моделей и все три этапа инференса. Подготовка моделей, первичная распаковка и проверка SHA-256 теперь также входят в показатель. Импорт файла до нажатия кнопки не входит. Исторические ранние прогоны исключали подготовку моделей и не сравниваются напрямую с новыми.
